Hack, Fix, Discuss! Security Edition

Welcome to the security edition of GroningenPHP workshops! Instead of building new features, we're going to break and fix existing ones.

Workshop Structure:
  • Hack: Team Red finds and exploits the vulnerability.
  • Fix: Team Blue refactors the code to be secure.
  • Discuss: We compare notes and discuss the "Best Practice" fix.

1. Your Sandbox

We'll use 3v4l.org to run our code. It's a free online PHP shell that supports almost every PHP version and includes common extensions like PDO (SQLite).

Challenge 1: The Gatekeeper

This mission is locked. Wait for the organizer to reveal the password.


Team Hack

Goal: Extract the admin_password from the system_config table.

The current query only fetches the username for a given ID. Can you use a UNION attack to pull data from another table?

Copy 
<?php
// --- SIMULATED INPUT ---
$userId = "1"; 
// -----------------------

$db = new PDO('sqlite::memory:');
$db->exec("CREATE TABLE users (id INT, username TEXT, role TEXT)");
$db->exec("CREATE TABLE system_config (config_name TEXT, config_value TEXT)");

$db->exec("INSERT INTO users VALUES (1, 'alice', 'user')");
$db->exec("INSERT INTO system_config VALUES ('admin_password', 'FLAG{UNION_BASED_PWNAGE}')");

// VULNERABLE CODE: Fetching username by ID
$query = "SELECT username FROM users WHERE id = " . $userId;
echo "Executing: $query\n\n";

$result = $db->query($query);

if ($result) {
    foreach ($result as $row) {
        echo "Result: " . $row['username'] . "\n";
    }
}

Team Fix

Goal: Patch the vulnerability using Prepared Statements.

The $userId should never be concatenated directly into the query string. Use placeholders instead.

Tip: Research $db->prepare() and $stmt->execute(['id' => $userId]).

Challenge 2: The Calculator

This mission is locked. Wait for the organizer to reveal the password.


Team Hack

Goal: Extract the value of the $flag variable.

The organizer added a filter to block the word "flag". Can you bypass this check using PHP's dynamic features?

Copy 
<?php
// --- SIMULATED INPUT ---
$expression = "1 + 1"; 
// -----------------------

$flag = "FLAG{BYPASSING_THE_FILTER}";

echo "Result: ";

// NAIVE FILTER: Blocking the word 'flag'
if (preg_match('/flag/i', $expression)) {
    die("Hack detected: No flags allowed!");
}

// DANGEROUS: Evaluating user input
eval("echo " . $expression . ";");

Team Fix

Goal: Prevent any code execution.

Ensure that the input passed to eval() (or any execution function) is strictly validated or avoid eval() entirely.

Tip: Try using a whitelist of allowed characters (numbers and operators) or a safer way to evaluate math.

Challenge 3: The File Explorer

This mission is locked. Wait for the organizer to reveal the password.


Team Hack

Goal: Read the config.php file located outside the pages/ directory.

The developer tried to block ../. Is the filter strong enough? Think about how str_replace works.

Copy 
<?php
// --- SIMULATED INPUT ---
$page = "bio"; 
// -----------------------

// --- SANDBOX SETUP ---
$base = sys_get_temp_dir() . "/workshop_" . getmypid() . "/";
@mkdir($base); @mkdir($base . "pages");
file_put_contents($base . "pages/bio.php", "This is the bio page.");
file_put_contents($base . "config.php", "<?php \$flag = 'FLAG{NESTED_TRAVERSAL_BYPASS}'; echo \$flag;");

// NAIVE FILTER: Removing ../
$page = str_replace("../", "", $page);

// VULNERABLE CODE
$requestedPage = "pages/" . $page . ".php";
echo "Loading: $requestedPage\n\n";

if (file_exists($base . $requestedPage)) {
    include($base . $requestedPage);
} else {
    echo "Page not found.";
}

Team Fix

Goal: Sanitize the file path to prevent traversal.

Don't trust user input for file paths. Use functions like basename() or realpath() to ensure the file is where it should be.

Tip: Use basename($page) to strip any directory information from the input.

Challenge 4: The Magic Box

This mission is locked. Wait for the organizer to reveal the password.


Team Hack

Goal: Trigger the AdminProfile logic by providing a custom serialized string.

The User class now uses a profile object. Can you craft a serialized string that swaps the GuestProfile with an AdminProfile?

Copy 
<?php
// --- SIMULATED INPUT ---
// Serialized User with a GuestProfile
$data = 'O:4:"User":1:{s:7:"profile";O:12:"GuestProfile":0:{}}'; 
// -----------------------

class User {
    public $profile;
    public function __wakeup() {
        $this->profile->display();
    }
}

class GuestProfile {
    public function display() {
        echo "Welcome, guest.";
    }
}

class AdminProfile {
    public function display() {
        echo "Welcome Admin! FLAG{DESERIALIZATION_POP_CHAIN}";
    }
}

// DANGEROUS: Unserializing user input
unserialize($data);

Team Fix

Goal: Replace unserialize with a safer format.

Never use unserialize() on user-provided data. Use json_decode() instead for data exchange.

Tip: JSON doesn't support object instantiation or magic methods, making it much safer.
